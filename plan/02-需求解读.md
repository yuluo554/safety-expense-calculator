# 02 需求解读（痛点 → 能力转译 / FR 清单 / NFR / 边界守卫）

> 上游：[01-题目详细定义.md](01-题目详细定义.md) v1（2026-10-14 定稿）。本文把"题目要求"转译成可判定、可验收的功能需求（FR）与非功能需求（NFR），并把**边界守卫**写成可执行纪律。
> 术语：**计提**＝按办法标准计算应提取金额；**依据量**＝产量（吨）/ 营业收入（元）/ 建筑安装工程造价（元）；**超额累退**＝分段适用不同费率；**规则包**＝按"依据文件 × 版本"组织的机器可读计提标准。

---

## 一、痛点 → 能力转译

| # | 企业侧真实痛点 | 现状（人工/通用工具） | 本工具能力（可判定形态） | 对应 FR |
|---|---|---|---|---|
| P1 | **口径易错**：同一企业按行业、按产量或按营业收入（超额累退）或按工程造价（比例）计提，跨行业混合经营时"按哪条计提"本身就是一道题 | 财务软件只给科目提示；咨询给模板表 | 计提依据选择判定引擎：按档案属性（行业/是否跨行业/是否承揽承运/是否多种灾害并存矿井）**显式判定并留痕**，输出选定依据与排除理由 | FR-1、FR-5 |
| P2 | **分段不会算**：超额累退"分段"逐段费率不同，人工按总额乘单一费率即错 | Excel 手算、口径各异 | 分段计算器：逐段分解（段区间 / 依据量 / 费率 / 段内金额 / 条款），**恰好等于分段点**的归属显式定义并可枚举验证 | FR-2 |
| P3 | **版本易混**：2012 版与 2022 版数值大面积不同，用新版标准重算旧台账即失真 | 无版本概念 | 双版本规则集 + **按年度锚定版本**；历史年度回算自动取当年有效版本 | FR-3、FR-4 |
| P4 | **核查无据**：专项审计要求"每笔计提挂条款、每笔支出对得上使用范围"，人工翻 69 条比对既慢又不可复现 | 无结构化检查项 | 计提结论挂条款号；支出明细逐笔映射到"应当用于以下支出"条目，四态判定挂条款 | FR-1、FR-6 |
| P5 | **"去年提够没有"**：使用进度门槛（不足某比例须披露并书面说明）是常态化义务，容易被漏 | 无门槛判定 | 使用进度门槛判定 + 披露义务生成说明要点 | FR-7 |
| P6 | **台账以千条计**：逐笔点开不现实 | 人工抽样 | 批量扫描 + 失败件隔离 + 跨年对账（新增异常/已修复/持续异常） | FR-8、FR-9 |
| P7 | **结论要能交给审计/存档**：口径要能离线复现、留指纹防篡改 | 手工 Word 报告 | 报告导出（Markdown + XLSX）+ 台账/结果 sha256 指纹 + 规则包坐标表头 | FR-10、FR-11 |

**转译原则**：每条痛点都必须落到"**有输入契约、有确定性输出、有条款依据、可被基准回归**"的能力上；不落成"给个建议"这类不可判定形态。

## 二、功能需求清单（FR，带优先级与验收判据）

优先级：**P0 = 首期必需（不进则首期不成立）**；P1 = 首期应做；P2 = 首期留扩展（接口预留、实现可后置）。

### 规则与门控（确定性纪律的载体）

| FR | 名称 | 优先级 | 输入 | 输出 | 验收判据 |
|---|---|---|---|---|---|
| FR-1 | **规则包加载与 status 门控** | P0 | `data/rules/`（manifest + 双版本规则集） | 生效规则集 / 门控结论 | ① `pending` 条目**绝不进入计算路径**（构造 pending 依赖 → 计算被拦截，退出码 1，原因逐条列出）；② 门控**按计算路径分作用域**（`calc`/`check`/`progress`），互不误伤；③ 无 `pending` 阻断时计算可完成；④ 门控结论可复现（同输入同输出） |
| FR-2 | **规则包元数据与规则集清单** | P0 | manifest.json | 规则集坐标（依据文件/版本/生效年度/来源 URL/抓取日期/sha256） | 报告头**必含**规则包坐标；`safefee rulesets` 可列出全部规则集与状态 |
| FR-3 | **年度 → 版本锚定（历史年度回算）** | P0 | 年度 | 该年度适用的规则集 | 2012–2022 年度锚定旧版；2022 起锚定 2022 版；**不存在的年度区间显式报错**（退出码 2），不静默取最新版 |
| FR-4 | **双版本差异对照** | P1 | 两个规则集 | 数值差异报告 + 新增/删除条款 | 同一计提对象两版数值逐条对照；差异项挂两版条款；差异报告可导出 |
| FR-5 | **单元换算与单位口径一致性** | P0 | 金额/产量字面量 + 单位 | Decimal 金额 | 元/万元/亿元换算由 `units.json` 承载（定义性事实）；**单位口径不一致（元 vs 万元）须报 warning 而非静默换算**；全链路 Decimal，禁浮点直算 |

### 计提引擎（确定性内核）

| FR | 名称 | 优先级 | 输入 | 输出 | 验收判据 |
|---|---|---|---|---|---|
| FR-6 | **三类计提机制计算** | P0 | 企业档案（行业/依据量/年度） | 应计提金额 + 公式 + 条款依据 + 逐段/逐档明细 | ① 按产量（煤炭等）；② 按营业收入超额累退；③ 按工程造价比例——三机制均有正文算例；金额精确到分（`ROUND_HALF_UP`）；**结论旁挂"第 X 条"** |
| FR-7 | **计提依据选择判定** | P1 | 档案属性（跨行业/承揽承运/多种灾害并存/矿井类型） | 选定依据 + 排除依据 + 判定留痕 | 跨行业经营、承揽/承运净额口径、多种灾害并存从高提取等规则显式判定并留痕；**依据缺失即索取（退出码 2），绝不静默取 0/1** |
| FR-8 | **超额累退逐段可溯** | P0 | 依据量（营业收入） | 段明细表 + 合计 | 每段输出 段下界/段上界/段内依据量/费率/段内金额/累计金额/条款；**恰好等于分段点**的归属在基准中枚举验证；逐段明细可随报告导出 |

### 支出核查与进度

| FR | 名称 | 优先级 | 输入 | 输出 | 验收判据 |
|---|---|---|---|---|---|
| FR-9 | **支出范围合规核查（四态）** | P0 | 支出明细台账（科目/摘要/金额） | 逐笔 符合/部分符合/不符合/不适用 + 条款依据 | 支出范围条目结构化（编号/节次/条款/可列支/不可列支/判定标准）；**禁止性红线项单列**（不得侵占挪用、不得替代其他资金渠道）；不得侵占等无条件义务缺失 = `不符合` |
| FR-10 | **使用进度与披露核查** | P1 | 年度应计提额 + 实际使用额 | 是否触发披露义务 + 说明要点 | 门槛值由规则包承载（不硬编码）；触发与否判定可复现；**未达门槛 → 输出披露义务与要点，不得静默通过** |
| FR-11 | **批量台账扫描（失败件隔离）** | P0 | 目录/清单（多企业 × 多年度） | 逐件结论 + 失败件单列 | 单件异常不中断整批；失败件带原因码（`parse_error`/`missing_field`/`unknown_industry`）；**失败件 ≠ 违规**（不改退出码） |

### 对账、基准与交付物

| FR | 名称 | 优先级 | 输入 | 输出 | 验收判据 |
|---|---|---|---|---|---|
| FR-12 | **跨年对账（两轮）** | P1 | 本轮结果 + 上轮结果（baseline） | 新增异常/已修复/持续异常/稳定 四集合 | 配对主键 = **稳定身份键**（企业号 + 年度），非内容指纹；内容变化另立 `content_changed` 标记；四集合划分由单一实现源产出 |
| FR-13 | **内置评测基准（零 API）** | P0 | 随包规则包 + 合成真值库 | 基准报告 + 达标率 | 三类套件：分段边界枚举 / 双版本对照 / 合成台账真值对账；**零第三方依赖、零外网、单次 <1 秒**；指标口径写进 README；每套件配**可证伪探活** |
| FR-14 | **证据链与指纹** | P1 | 台账 + 结果 | sha256 指纹随底稿固化 | 台账与结果整体 sha256；报告产物自身 sha256 进 evidence；**被改动即可检出** |
| FR-15 | **报告导出（MD + XLSX）** | P1 | 计算/核查结果 | 人读 Markdown + 机读 XLSX | 单一渲染源（两格式内容一致是**结构性质**）；机读产物**无外链**（断网可开）；**含参数来源块**（发布机关/年度/文号/URL/抓取日期）；未启用章节显式写出；溯源完整性硬约束（行数对账 + 引用 id 可解析） |
| FR-16 | **桌面 GUI（PySide6）** | P1 | — | 多页签界面 | **只消费引擎 API、零判定逻辑**（AST 静态门禁三条齐上：不 import 规则层 + 无算术 `BinOp` + 无政策数值字面量）；与 CLI **行为等价**（三方对账：CLI stdout == 编排直调 == 报告章节） |

## 三、非功能需求（NFR）

| NFR | 内容 | 验收方式 |
|---|---|---|
| NFR-1 **零依赖核心层** | 引擎/规则加载/分段/对账/基准**不引第三方库**（标准库 + Decimal 足够） | 核心层 import 面静态断言（AST）：核心模块不得 import 非标准库 |
| NFR-2 **全本地零上传** | 默认不联网；无任何出网调用（不发 HTTP、不解析远程 URL） | 源码静态扫描无 `requests`/`urllib.request`/`http.client` 出网调用；基准与测试全离线 |
| NFR-3 **字节可复现** | 规则包为冻结产物：**再生成逐字节一致**；报告（文本 + XLSX）同输入逐字节一致 | 生成器 `--check` 逐字节比对；报告两轮导出 sha256 一致；zip 容器固定 `create_system`/时间戳 |
| NFR-4 **Python 3.12+ 兼容**（**2026-10-19 由 3.8+ 抬升，DEC1，见 06 E29**） | 支持 3.12（CI 双矩阵） | CI 矩阵 ubuntu/windows × 3.12 全绿 |
| NFR-5 **编码健壮** | 中文输出在 cp1252/cp936 管道下不崩 | 入口 `_ensure_utf8_stdio()` 探针 reconfigure；测试用 cp1252 流复现 |
| NFR-6 **退出码契约** | 0 成功 / 1 门控拦截或基准未达标 / 2 输入或用法错误 / 3 可选依赖缺失 | 三语义锁进 CLI 测试；`--only` 未知名 → 2 |
| NFR-7 **可核证交付物** | 每条结论可追到规则条目；报告自带参数来源块 | 导出前断言：溯源表行数 == 明细行数 + 参数行数，引用 id 可解析 |
| NFR-8 **判定语义不虚高** | `不适用` 只给"原文写了例外情形"的项；无条件义务缺失 = `不符合`；无适用项 → `未评估`（不输出 `符合`） | 支出核查四态语义测试；无适用条目时输出 `not_assessed` |
| NFR-9 **脱敏与免责** | 台账一律合成；免责声明强制随报告输出 | 合成企业白名单（虚构名称 + `90000000…SYN` 号段）；报告含免责声明断言 |

## 四、边界与非目标（守卫清单，逐条可执行）

> 下列条目不是"说明"，而是**要落成测试或门禁**的守卫；每条都写明落点，防止 scope 失控。

| # | 边界 | 落点（怎么守住） |
|---|---|---|
| B1 | **不做会计记账/凭证生成**（不替代财务软件） | 输出面只到"应计提金额 + 依据"；无凭证/分录生成代码路径；README「限制」节显式声明 |
| B2 | **不做税务处理与税前扣除判定** | 无任何税率/扣除字段；规则包 schema 无税务字段（结构上杜绝） |
| B3 | **不出具审计意见** | 报告固定含免责声明（测试断言）；结论措辞为"测算/检查发现"，禁用"审计意见/鉴证" |
| B4 | **不对接监管申报接口** | NFR-2 零出网门禁；无申报报文生成 |
| B5 | **不做真实企业数据采集** | 输入一律本地文件；合成台账纪律（虚构名称 + 测试号段白名单） |
| B6 | **首期范围**：136 号全部十二节计提标准 + 2012 版历史对照；支出范围与进度核查首期煤炭/建设工程/危险品/电力四行业 | 规则包 `industries[]` 的 `implementation` 字段标 `in_scope`/`deferred`；`deferred` 行业被请求时返回"首期未覆盖"（退出码 2）而**不臆造结论** |
| B7 | **未挂原文核对不得进入计算路径** | FR-1 门控（`status=pending` 阻断 + 分作用域） |
| B8 | **不编造标准内容**：核对记录未覆盖的条目**不建规则** | 规则条目必挂 `provenance`（文号/条款/URL/抓取日期/核对状态）；无 provenance 的条目生成器拒绝产出 |
| B9 | **品牌隔离**：不复制姊妹项目代码；公开文档不提其余项目业务领域 | 脱敏扫描器词表（含系列词族）随仓；README/plan 只描述本题领域 |
| B10 | **数据纪律**：demo/基准一律合成台账，禁真实企业数据 | 合成台账生成器为唯一写入者；台账登记来源与许可 |
