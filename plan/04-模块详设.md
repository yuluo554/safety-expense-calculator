# 04 模块详设

> 上游：[03-架构与技术选型.md](03-架构与技术选型.md)。本文定各模块的输入/输出契约、数据结构、算法与退出码，供实现时逐条对照。
> 金额一律 `Decimal`；JSON 读入用 `parse_float=Decimal`；呈现/落盘统一两位小数 `ROUND_HALF_UP`。

## 1. 规则包加载与门控（`safefee.rules`）

### 1.1 `data_paths.find_data_dir(explicit=None)`

优先级（**改优先级属"动了会打挂测试"的口径变更**）：

1. `explicit`（CLI `--data-dir`）
2. 环境变量 `SAFEFEE_DATA_DIR`
3. 冻结态：`sys._MEIPASS/data`（PyInstaller 6）→ `exe目录/_internal/data`（PyInstaller 5 兼容）
4. 源码态：自 `__file__` 上溯找含 `data/rules/manifest.json` 的目录
5. 兜底：CWD 上溯

返回 `Path`；找不到抛 `DataDirNotFound`（退出码 2）。

### 1.2 `manifest.load_manifest(data_dir) -> Manifest`

- 校验 `schema_version`（未知 → `SchemaError`）；
- 校验每个 `rulesets[].sha256` 与磁盘文件实际指纹一致（不一致 → `IntegrityError`，说明规则包被手改）。
- 暴露 `manifest.benchmark_thresholds`（**基准门槛唯一来源**）。
- 暴露 `resolve_ruleset(year) -> RulesetRef`：按 `effective_from_year <= year <= effective_to_year`（`None` = 无上界）匹配；**无一匹配 → `NoRulesetForYear`（退出码 2）**；多匹配 → `AmbiguousRuleset`（配置错误）。

### 1.3 `gate.check_scope(ruleset, scope) -> GateResult`

```python
@dataclass(frozen=True)
class GateBlocker:
    path: str        # 如 "industries[0].variants[1]"（条目定位，供留痕）
    clause: str      # 条款号
    status: str      # "pending"
    reason: str

@dataclass(frozen=True)
class GateResult:
    scope: str                    # calc | check | progress
    ok: bool
    blockers: tuple[GateBlocker, ...]
```

- `scope="calc"`：遍历该规则集的全部 mechanism/variant/segment；`status != "verified"` 即 blocker。
- `scope="check"`：遍历 `spending.json` 的条目。
- `scope="progress"`：遍历 `progress.json` 的门槛项。
- `status == "input_required"` **不产生 blocker**（放行，运行时必索）。
- **不实现在 CLI 层**：CLI 只渲染 `GateResult`。

## 2. 年度 → 版本锚定与双版本对照（`safefee.ruleset`）

### 2.1 `anchor.resolve(year, manifest) -> RulesetRef`

见 1.2。**纪律**：指定年度即锚定版本，**杜绝"用新版标准重算旧台账"**。年度区间表：

| 年度 | 适用版本 |
|---|---|
| ≤ 2022-11-20 | 财企〔2012〕16号（旧版） |
| ≥ 2022-11-21 | 财资〔2022〕136号（新版） |

> 办法"自印发之日起施行"，故**按日**而非按年锚定；档案若只给年度，取该年度 1 月 1 日为锚定日（口径写进模块注释与报告参数块）。

### 2.2 `diff.compare(rs_old, rs_new, object_key) -> DiffReport`

- 按 `(industry_id, variant_id)` 配对；
- 输出四类：`value_changed`（数值差异）/ `rate_changed`（费率差异）/ `added`（新增条款）/ `removed`（删除条款）；
- 每条差异挂两版条款号与 provenance。

## 3. 三类计提机制（`safefee.accrual`）

### 3.1 统一输入契约

```python
@dataclass(frozen=True)
class AccrualRequest:
    industry_id: str
    variant_id: str | None       # 如矿井类型；无变体则 None
    basis_kind: str              # "output" | "revenue" | "project_cost"
    basis_value: Decimal         # 依据量（吨 / 元 / 元）
    basis_unit: str              # 输入单位（"ton" | "CNY" | "CNY10k" | "CNY100m"）
    year: int
```

### 3.2 统一输出契约

```python
@dataclass(frozen=True)
class AccrualResult:
    amount: Decimal                  # 应计提金额（量化到分，ROUND_HALF_UP）
    mechanism: str                   # by_output | by_revenue_tiered | by_project_cost
    formula: str                     # 人类可读公式（数值全部来自规则包）
    clause: str                      # 条款依据
    tiers: tuple[TierLine, ...]      # 逐段/逐档明细（比例类单行、分段类多行）
    provenance: tuple[Provenance, ...]
```

### 3.3 三机制算法

| 机制 | 公式 | 边界要点 |
|---|---|---|
| `by_output`（按产量） | `amount = value(CNY/ton) × quantity(ton)` | 变体由 `variant_id` 选定（突出矿井 / 高瓦斯 / 其他井工 / 露天）；**多灾害并存从高提取**由 `basis.py` 判定后单选变体 |
| `by_revenue_tiered`（超额累退） | 逐段 `Σ (段内依据量 × 段费率)`，见 §4 | 段边界归属 `[lower, upper)`，**恰好等于分段点归下一段** |
| `by_project_cost`（造价比例） | `amount = rate × project_cost` | 工程类别由 `variant_id` 选定；费率来自规则包 |

**单位换算**（`rules/units.py`，数值来自 `units.json`）：输入 `basis_unit` 与规则包期望单位不一致时——

- 可**定义性精确换算**（如 `CNY10k → CNY`）：换算并记 `warning`（附"输入单位口径与规则包期望不同，已按定义换算"）；
- **不可判定**：报错（退出码 2），**不静默猜测**。

> 纪律：元/万元错配是真实高频事故，**必须报 warning 而非静默通过**（也是合成真值库的注入项之一）。

## 4. 超额累退分段计算器（`safefee.tiered`）

```python
@dataclass(frozen=True)
class TierLine:
    index: int             # 段序号（1 起）
    lower: Decimal         # 段下界（含）
    upper: Decimal | None  # 段上界（不含）；None = 无上界
    base_in_tier: Decimal  # 段内依据量
    rate: Decimal          # 段费率
    amount: Decimal        # 段内金额（量化到分）
    clause: str

def compute_tiered(value: Decimal, tiers: Sequence[TierSpec], *, quantize=Q2) -> tuple[TierLine, ...]
```

**算法**：

```
remaining = value
for tier in tiers:
    if tier.upper is None:
        base = max(remaining, 0)
    else:
        base = min(max(remaining, 0), tier.upper - tier.lower)
    line = TierLine(base_in_tier=base, amount=quantize(base * tier.rate), ...)
    remaining -= base
    if remaining <= 0: break
```

**边界口径（定稿）**：段区间 `[lower, upper)`；`value == upper` 时该段取满、余量进下一段。`Σ段内金额` 即合计（**逐段量化后求和**，与"总额乘单一费率"不同——这正是工具的存在理由）。

**基准确认**：`bench` 的 `tiered_boundary` 套件对每个分段点做 `{point-0.01, point, point+0.01}` 三点枚举，断言段归属与金额。

## 5. 计提依据选择判定（`safefee.accrual.basis`）

输入档案补充属性，输出**选定依据 + 排除依据 + 判定依据条款**：

```python
@dataclass(frozen=True)
class BasisDecision:
    chosen: str                  # 选定的 basis_kind / variant_id
    excluded: tuple[tuple[str, str], ...]   # (被排除项, 排除理由)
    clause: str
    inputs_required: tuple[str, ...]        # 缺失即退出码 2 的字段
```

判定规则（首期）：

| 场景 | 判定 | 依据 |
|---|---|---|
| 跨行业经营 | 按**主营行业**或不适用则分别计提（规则包声明） | 办法适用条款（M1 逐条核对后落值） |
| 承揽/承运净额 | 净额口径适用条件判定并留痕 | 第五十三条 |
| 多种灾害并存矿井 | **从高提取**（选费率最高变体） | 第七条 |
| 档案属性缺失 | `inputs_required` 列出缺失字段 → **退出码 2** | 纪律：绝不静默取 0/1 |

## 6. 支出范围合规核查（`safefee.spending`）

### 6.1 支出条目编码（`spending.json`）

```jsonc
{
  "entries": [
    { "entry_id": "SP-C-01", "industry_id": "coal", "clause": "第八条",
      "category": "允许",              // 允许 | 禁止（红线）
      "criterion": "…（要点引用，非全文转载）",
      "match_keywords": ["…"],        // 规则优先匹配
      "status": "pending", "provenance": {...} }
  ]
}
```

### 6.2 四态判定语义（**不虚高**）

| 判定 | 何时给 | 反例（禁止） |
|---|---|---|
| `符合` | 命中允许条目且无禁止命中 | — |
| `部分符合` | 同时命中允许与禁止，或命中允许但摘要含限制条件 | — |
| `不符合` | 命中禁止条目，或**无条件义务缺失** | 不得侵占挪用（红线）|
| `不适用` | **原文明确写了例外情形**且该情形成立 | ❌ 不得用于"缺材料/用户没做" |

- **无适用条目时**：输出 `未评估`（`not_assessed`），**绝不输出 `符合`**（"没查出问题" ≠ "没检查过"）。
- **红线项单列**：`category="禁止"` 的命中在报告单列一节。
- 首期覆盖煤炭/建设工程/危险品/电力；其余行业被请求 → 返回"首期未覆盖"（退出码 2）。

## 7. 使用进度与披露（`safefee.spending.progress`）

```python
@dataclass(frozen=True)
class ProgressResult:
    year: int
    accrued: Decimal          # 年度应计提额
    used: Decimal             # 当年实际使用额
    ratio: Decimal            # used / accrued（accrued=0 时显式特殊处理）
    threshold: Decimal        # 门槛（来自规则包，非硬编码）
    disclosure_required: bool
    points: tuple[str, ...]   # 披露说明要点
```

- 门槛值（第五十一条）来自 `progress.json`；`accrued = 0` 时返回 `not_applicable`（原文语义）而非除零。

## 8. 批量扫描与对账（`safefee.batch`）

### 8.1 批量扫描

```
safefee scan <目录或清单> --out <报告目录> [--baseline <上轮结果.json>]
```

- 逐件解析 → 计提 + 核查；**单件异常不中断整批**；
- 失败件带原因码：`parse_error` / `missing_field` / `unknown_industry` / `unsupported_container` / `too_large`；
- **失败件 ≠ 违规**：失败件单列，**不改退出码**（退出码仍由"是否检出不符合/门控"决定）。

### 8.2 跨年对账（四集合）

| 集合 | 定义 |
|---|---|
| `新增异常` | 本轮非 pass，上轮 pass 或无记录 |
| `已修复` | 上轮非 pass，本轮 pass |
| `持续异常` | 两轮均非 pass |
| `稳定` | 两轮均 pass |

- **配对主键 = 稳定身份键**（`enterprise_id` + `year` + `item_key`），**不是内容指纹**；
- 内容变化另立 `content_changed` 标记（避免退化成"新增 + 移除"）；
- 对账口径**单一实现源**（`batch/reconcile.py` 的 `compare_nonpass`），真值测试与基准共用；
- **非 pass = fail ∪ unknown**；`不适用`/`未评估` 排除在比较外（那是"没看到"不是"缺失"）。

## 9. 证据链与指纹（`safefee.evidence`）

- 每份台账/结果挂 `content_sha256`；
- 报告产物自身 sha256 进 `evidence.json`；
- **可复现要求**：报告（Markdown 与 XLSX）**同输入逐字节一致**——XLSX 走自写 writer（`ZIP_STORED` + `create_system=0` + 固定 `date_time`），Markdown 走固定换行 + 无时间戳。

## 10. 报告导出（`safefee.report`）

### 10.1 单一渲染源

```
sections.build(result) -> list[Section]      # 唯一章节结构源
report.markdown.render(sections) -> str      # Markdown 渲染器
report.xlsx.render(sections) -> bytes        # XLSX 渲染器（自写 OOXML）
```

**两格式内容一致是结构性质**（同一 `Section` 列表 → 两个渲染器），不靠人工比对。

### 10.2 报告固定章节

| # | 章节 | 内容 |
|---|---|---|
| 0 | **规则包坐标**（报告头） | 依据版本 + 版本号 + 生成时间 + manifest sha256 |
| 1 | 企业档案 | 合成企业标识、行业、年度、依据量 |
| 2 | 逐条计提明细 | 金额 + 公式 + 条款 + **逐段明细表**（段/依据量/费率/段内金额） |
| 3 | 支出合规核查清单 | 逐笔四态 + 条款；**红线项单列** |
| 4 | 使用进度与披露 | 进度比例 + 是否触发披露 + 要点 |
| 5 | 异常与对账台账 | 新增/已修复/持续异常 三集合 |
| 6 | **参数来源块** | 每项参数：发布机关 + 适用年度 + 文号 + URL + 抓取日期 |
| 7 | 免责声明 | 固定文本；**口径为"测算/检查发现"，非审计意见** |

- **未启用章节显式写出**（如"本次导出未启用支出核查（用 --with-check 启用）"），不留空；
- **溯源完整性硬约束**：导出前断言溯源表行数 == 明细行数 + 参数行数，且每个引用 id 可解析（不满足即拒导、退出码 1）；
- 生成时间只进报告头（**报告可复现性例外项**：如要求字节一致，`--fixed-time` 固定；默认写实际时间并在测试中用固定时间断言结构一致性）。

> 口径澄清：**"报告逐字节可复现"**按"同输入 + 同 `--fixed-time` + 两次导出"断言；默认含真实生成时间，二者由参数区分（写进 README 与测试）。

## 11. 编排层（`safefee.engine.pipeline`）

公开函数组（CLI 与 GUI 唯一入口）：

| 函数 | 作用 |
|---|---|
| `build_case(archive: dict) -> Case` | 档案校验 + 归一（输入格式解释的唯一实现） |
| `resolve_ruleset_for(year) -> RulesetRef` | 年度锚定 |
| `compute_calc(case) -> CalcReport` | 门控 → 计算 → 结果 |
| `check_ledger(case, ledger) -> CheckReport` | 支出核查 |
| `compute_progress(case) -> ProgressResult` | 进度判定 |
| `scan(paths, baseline=None) -> ScanReport` | 批量 + 对账 |
| `export_report(report, out_dir, formats) -> tuple[Artifact, ...]` | 报告导出 + 指纹 |
| `selfcheck() -> dict` | 数据目录/规则集/门控计数（`safefee selfcheck`） |

**约束**：CLI/GUI 只准经这些入口取数；`build_case` 是输入校验的唯一实现（GUI 不得自带校验）。

## 12. CLI 命令与退出码

```
safefee selfcheck                       # 数据目录定位 + 规则集加载 + 门控计数
safefee version
safefee rulesets [--json]               # 规则集清单与状态
safefee units                           # 单位换算表
safefee calc <档案.json> [--json] [--year N] [--data-dir D]
safefee check <台账.csv|xlsx> [--json] [--with-progress]
safefee progress <档案.json> --used <金额>
safefee scan <目录> --out <目录> [--baseline B.json]
safefee diff --from-year N --to-year M  # 双版本差异对照
safefee bench [--only SUITE] [--json]
safefee gui                             # 惰性导入 PySide6（缺依赖 exit 3）
```

| 退出码 | 语义 |
|---|---|
| 0 | 成功（基准全达标；无检出不符合） |
| 1 | 门控拦截 / 基准未达标 / 检出不符合 |
| 2 | 输入或用法错误（含年度无规则集、`deferred` 行业、`--only` 未知名） |
| 3 | 可选依赖缺失（GUI、xlsx 台账读入） |

`bench --only` 白名单：`tiered_boundary`、`dual_version`、`synthetic_ledger`；未知名 → **2**。

## 13. 基准（`safefee.bench`）

| 套件 | 类型 | 内容 | 达标门槛（来自 manifest） |
|---|---|---|---|
| `tiered_boundary` | **规则驱动** | 从规则表推导全部分段点，做 `{p-0.01, p, p+0.01}` 枚举，断言段归属与逐段金额自洽 | `min_pass_ratio: 1.0` |
| `dual_version` | 规则驱动 | 同一对象按两版规则各算期望值，断言版本切换结果与两版原文一致 | `min_consistency: 1.0` |
| `synthetic_ledger` | **样本驱动** | 合成台账真值库全量重算对账（独立实现路径） | `min_truth_match: 1.0` |

- **零第三方依赖、零外网、单次 <1 秒**；
- **每套件配可证伪探活**：注入一个缺陷 → 断言基准变红（防"基准什么都没查"）；
- **样本驱动 vs 规则驱动分层**：`tiered_boundary`/`dual_version` 不读真值库，专治"样本没覆盖的端点"；
- 门槛缺失 → 退出码 2（**不得回落代码默认值**）；
- `--only` 部分运行时不判定未测指标（"没测" ≠ "未达标"）。

## 14. 冻结产物与生成器（`tools/`）

| 工具 | 产出 | 守门 |
|---|---|---|
| `tools/gen_rulesets.py` | `data/rules/**`（manifest/units/双版规则集/支出/进度） | `--check` 再生成逐字节一致；初态**全部 `pending`、`value: null`**（未核对不得落值） |
| `tools/gen_synthetic.py` | `data/truth/**`（合成企业台账 + 真值 + 误报对照集） | 确定性 RNG（splitmix64）；`--check` 逐字节一致 |
| `tools/dessensitize_audit.py` | 脱敏审计（tracked/history/messages 三模式 + selftest） | `DESSENSITIZE_AUDIT_OK` 标记；命中分级 HARD/REVIEW/advisory |
| `tools/build_datas.py` | PyInstaller datas 白名单（**不叫 `packaging.py`**，避免遮蔽 PyPI `packaging`） | spec 文本守门 + 构建后三断言（M5/M6） |

**M0 范围**：`gen_rulesets.py` 产出**结构完整但值全 `pending`** 的规则包（十二节行业条目 + 机制骨架 + units + manifest），使门控/CLI/CI 链路可端到端跑通；**具体数值留 M1 逐条核对后落库**。
