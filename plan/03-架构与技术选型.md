# 03 架构与技术选型

> 上游：[02-需求解读.md](02-需求解读.md)。本文定分层架构、规则包 schema、目录布局、技术选型与关键工程纪律。
> 核心原则：**核心层零第三方依赖 + 规则包即数据 + 全链路 Decimal + 未核对不进计算路径**。

---

## 一、技术选型

| 维度 | 选型 | 理由 | 备选与排除 |
|---|---|---|---|
| 语言 | **Python 3.12+**（CI 覆盖 3.12；2026-10-19 DEC1 由 3.8 抬升，见 06 E29） | 系列惯例；核心功能无需第三方即可跑；分发用 PyInstaller | 排除 Node（不含税/计价类数值精度生态）；排除 Rust/Go（开发速度与系列一致性）；排除已 EOL 的 3.8–3.11 |
| 数值 | **`decimal.Decimal` 全链路** | 金额精确到分、分段边界可比（元 vs 万元）；float 尾差会使边界断言失效 | 排除 float（禁用；零字面量门禁同族纪律）；`fractions` 无需 |
| 数据格式 | **JSON（规则包/真值/档案）+ CSV（台账）+ XLSX（报告，可选）** | JSON 可 diff、可冻结、可 sha256；CSV 零依赖；XLSX 走惰性导入 | 排除 SQLite（无查询需求、破坏"冻结产物"形态）；排除 YAML（解析依赖 + 隐式类型坑） |
| CLI | **argparse（标准库）** | 零依赖；退出码语义可控 | 排除 click/typer（无必要依赖） |
| GUI | **PySide6**（惰性导入，额外组 `[gui]`） | 系列惯例；跨平台；offscreen 可测 | 排除 Tkinter（组件弱、中文渲染差）；排除 Electron（体积/构建链） |
| 打包 | **PyInstaller onedir，双 exe（GUI console=False + CLI console=True）** | 免安装；数据内嵌白名单；**打 GUI 必须 ≥6** | 排除 onefile（启动慢、杀毒误报多）；排除 Nuitka |
| 报告 XLSX | **自写最小 OOXML writer**（`zipfile` + 固定元数据） | 免第三方即可保证**逐字节可复现**；引 openpyxl 会有时间戳漂移 | openpyxl 仅作**可选**读入通路（台账导入），惰性导入 |
| 台账 XLSX 读入 | **openpyxl（惰性）**，缺依赖降级 CSV（exit 提示不崩） | 用户台账多为 xlsx | 排除 pandas（重）；冻结态提示须分流（别叫用户 pip install） |
| 基准框架 | **自研 runner（零依赖）**，单命令跑全 | "零 API 依赖可重复"硬要求 | 排除 pytest 作基准入口（pytest 只做测试） |
| 测试 | **pytest**（dev extra） | 生态成熟；矩阵化跑 | — |
| CI | **GitHub Actions，双矩阵（ubuntu/windows × 3.12；2026-10-19 DEC1 起，见 06 E29）** | 环境差异前置暴露 | — |
| LLM | **不使用** | 纯确定性规则 + 结构化输入，无解析兜底需求 → 零 API 依赖、基准可离线跑 | 排除任何 API 调用（也是 NFR-2 的来源） |

## 二、分层架构

```
┌───────────────────────────────────────────────────────────────┐
│ 表现层  cli/（argparse 子命令）        gui/（PySide6 页签）       │
│         只消费编排层公开函数；零判定逻辑；零政策数值             │
├───────────────────────────────────────────────────────────────┤
│ 编排层  engine/pipeline.py                                     │
│         compute_calc / check_ledger / scan_batch / export_report│
│         —— 单一事实源：CLI 与 GUI 共用同一编排                  │
├───────────────────────────────────────────────────────────────┤
│ 领域层（核心层，零第三方依赖）                                  │
│  ├─ rules/      规则包加载 + manifest + status 门控（分作用域）  │
│  ├─ ruleset/    年度→版本锚定 + 双版本差异对照                   │
│  ├─ accrual/    三类计提机制（产量 / 超额累退 / 造价比例）       │
│  ├─ tiered/     超额累退分段计算器（逐段可溯 + 边界归属）        │
│  ├─ basis/      计提依据选择判定（跨行业/净额/从高）             │
│  ├─ spending/   支出范围核查（四态）+ 进度门槛 + 红线项          │
│  ├─ batch/      批量扫描（失败隔离）+ 跨年对账（四集合）         │
│  ├─ evidence/   sha256 指纹 + 证据链                            │
│  └─ report/     单一渲染源（章节结构）→ Markdown / XLSX 渲染器  │
├───────────────────────────────────────────────────────────────┤
│ 数据层  data/rules/（冻结规则包） data/truth/（合成真值库）       │
│         data/knowledge/（依据索引 + 原文快照） data/samples/     │
└───────────────────────────────────────────────────────────────┘
```

### 依赖方向铁律（AST 静态门禁守住，不靠自觉）

1. **核心层零第三方**：`safefee/` 下除 `cli/`、`gui/`、`report/xlsx.py`（纯 `zipfile`）外，**不得 import 非标准库**。
2. **GUI 不得直接 import 领域层内部模块**：唯一入口是 `engine/pipeline.py`（AST 断言）。
3. **GUI 零判定逻辑**（三条齐上）：不 import 规则层 + 无算术 `BinOp`（两侧非字符串字面量的 `* / - // % **`）+ 无政策数值字面量（与核心层同一份禁用 token 表）。
4. **CLI 与 GUI 行为等价**：三方对账测试（CLI stdout 金额 == 直接调编排的字段 == 报告章节金额）。

## 三、规则包 schema（"依据文件 × 版本"）

### 3.1 目录形态

```
data/rules/
├─ manifest.json              # 规则集索引 + 基准门槛（数据非代码）+ 版本坐标
├─ units.json                 # 定义性换算（1 万元 = 10000 元，1 亿元 = 10^8 元）
├─ 财资-2022-136/
│  ├─ ruleset.json            # 计提标准（十二节）
│  ├─ spending.json           # 支出范围条目（首期四行业）
│  └─ progress.json           # 使用进度门槛（第五十一条等）
└─ 财企-2012-16/
   ├─ ruleset.json            # 计提标准（九类，历史对照）
   └─ ...
```

> 目录名用 ASCII 友好形式（`财资-2022-136`），避免跨平台路径/打包编码问题；**文号原文写在 manifest 与条目 provenance 里**。

### 3.2 `ruleset.json` 顶层结构

```jsonc
{
  "ruleset_id": "财资-2022-136",
  "doc_no": "财资〔2022〕136号",
  "doc_title": "企业安全生产费用提取和使用管理办法",
  "issuer": ["财政部", "应急部"],
  "issued_date": "2022-11-21",
  "effective_from_year": 2022,      // 该版本自哪个纳税/会计年度起适用
  "effective_to_year": null,        // null = 至今有效
  "supersedes": "财企-2012-16",     // 废止的旧版本（第六十九条）
  "provenance": { "url": "...", "fetched_at": "2026-10-14", "sha256": "..." },
  "status": "pending",              // 规则集级门控状态
  "mechanisms": {
    "by_output": {...},             // 按产量计提（吨煤 N 元）
    "by_revenue_tiered": {...},     // 按营业收入超额累退
    "by_project_cost": {...}        // 按建筑安装工程造价比例
  },
  "industries": [                   // 十二节（2022）/九类（2012）
    {
      "industry_id": "coal",
      "industry_name": "煤炭生产",
      "clause": "第七条",
      "implementation": "in_scope",   // in_scope | deferred
      "mechanism": "by_output",
      "variants": [
        {
          "variant_id": "coal_gas_outburst",
          "condition": { "mine_type": "gas_outburst_or_rockburst" },
          "unit": "CNY/ton",
          "value": null,              // ← 未核对：值为 null，status=pending
          "status": "pending",
          "provenance": { "doc_no": "财资〔2022〕136号", "clause": "第七条",
                          "url": "...", "fetched_at": null, "verified": false }
        }
      ]
    }
  ]
}
```

### 3.3 超额累退段结构（`by_revenue_tiered`）

```jsonc
{
  "lower": "0",                 // Decimal 字符串（元），含
  "upper": "10000000",          // Decimal 字符串（元），不含；null = 无上界
  "rate": null,                 // 费率（字符串，如 "0.045"）——未核对为 null
  "status": "pending",
  "clause": "第二十一条",
  "provenance": {...}
}
```

**边界归属口径（定稿一次，写进模块注释）**：段区间为 **`[lower, upper)`**（下含上不含），与办法表述"不超过 X 元的部分 … 超过 X 元至 Y 元的部分"一致；**恰好等于分段点**归入**下一段**（即"超过 X 元"起点含）。该口径由基准的边界枚举套件守住（含 ±0.01 邻域）。

### 3.4 `manifest.json`（含基准门槛，数据非代码）

```jsonc
{
  "schema_version": 1,
  "generated_by": "tools/gen_rulesets.py",
  "rulesets": [
    { "ruleset_id": "财资-2022-136", "dir": "财资-2022-136",
      "doc_no": "财资〔2022〕136号", "effective_from_year": 2022,
      "effective_to_year": null, "status": "pending",
      "sha256": "<文件指纹>" }
  ],
  "benchmark_thresholds": {          // ← 门槛随 manifest 下发，基准层只读
    "tiered_boundary": { "min_pass_ratio": 1.0, "max_false_positive": 0 },
    "dual_version":    { "min_consistency": 1.0 },
    "synthetic_ledger":{ "min_truth_match": 1.0 }
  }
}
```

> **门槛缺失 → 基准退出码 2（配置错误）**，**不得回落代码默认值**（否则门槛成了"抄进代码的第二份真相"）。

### 3.5 status 门控（分作用域）

| 作用域 | 校验的条目 | 典型命令 |
|---|---|---|
| `calc` | 计提标准（ruleset 的 mechanism/variants/segments） | `safefee calc` |
| `check` | 支出范围条目（spending.json） | `safefee check` |
| `progress` | 使用进度门槛（progress.json） | `safefee progress` |

判定：某作用域引用的条目中**任一 `status != verified`** → 该作用域计算被拦截，**逐条列出待核对条目**，退出码 1。

**第三态 `input_required`**：表示"本不由规则包承载、须运行时索取的外部输入"（如企业档案里的产量/营业收入本身、随工况而异的修正系数）——**不阻断门控**，但运行时**必索**，缺失即退出码 2，**绝不静默取 0/1**。

判别口诀：**"未核对"（pending，拦门）与"本不由规则包承载"（input_required，放行但必索）是两回事。**

## 五、退出码契约

| 码 | 语义 | 触发例 |
|---|---|---|
| 0 | 成功 | 计算/核查/扫描完成；基准全部达标 |
| 1 | 门控拦截 或 基准未达标 或 检出违规 | pending 条目阻断；基准 pass_ratio < 门槛；支出核查检出 `不符合` |
| 2 | 输入/用法错误（含"首期未覆盖"） | 档案缺字段；年度无对应规则集；`--only` 传未知名；`deferred` 行业被请求 |
| 3 | 可选依赖缺失（GUI / openpyxl 台账读入） | 源码态缺 `[gui]`：提示安装；冻结态：提示"本发行包未内嵌" |

**纪律**：① 批量扫描中**失败件 ≠ 违规**（失败件带原因码、单列、不改退出码）；② 退出码三语义锁进测试；③ 冻结态降级提示必须分流（别叫 exe 用户 `pip install`）。

## 六、关键工程纪律（选型层面的红线段）

| # | 纪律 | 落点 |
|---|---|---|
| D1 | **规则包禁手改**，生成器 `tools/gen_rulesets.py` 为唯一写入者，配"再生成逐字节一致"守门测试 | tests/test_frozen_rulesets.py |
| D2 | **零政策字面量门禁**：规则包全部数值收编为禁用 token，扫描**引擎/CLI/GUI/基准源码（含 docstring 与注释）**，数值只能来自规则包 | tests/test_no_policy_literals.py + `--selftest` 阳性对照 |
| D3 | **溯源完整性**：导出前断言"溯源行数 == 明细行数 + 参数行数"且引用 id 可解析，不满足即拒导 | 报告导出路径 |
| D4 | **单调色/无外链**：报告产物与 XLSX 单元格无 URL（断网可开） | 报告测试硬断言 |
| D5 | **字节冻结两层**：文本行尾（`eol=lf` + CR 守门）与 zip 容器（`ZIP_STORED` + `create_system=0` + 固定时间戳）各有守门 | tests/test_bytes_freeze.py |
| D6 | **确定性生成**：生成器禁 stdlib `random`、禁 `set` 迭代序、禁系统时钟——自研 splitmix64 确定性 RNG | tools/gen_*.py |
| D7 | **数据文件 ≠ 命令输入**：真值库是带 `expect` 包装的记录，README 必须给"抽卡"可复制命令 | README 快速开始 |
| D8 | **编码三道加固**：入口 reconfigure（救用户）+ subprocess 显式 `encoding=`（无环境变量可替代）+ CI `env: PYTHONUTF8=1` | `_stdio.py`、tools 脚本、ci.yml |
| D9 | **可选依赖惰性导入**：`try` 包住**从 import 到调用完成**的整条路径；回归用 `__import__` 打桩断言 exit 3 | cli/cmd_gui.py、cli/cmd_check.py |
| D10 | **打包工具版本按"打什么"分档**：打 GUI 必须 PyInstaller ≥6；构建固定在"装了 ≥6 的通道"（本机 = py -3.12） | tools/verify_package.py、决策记录 |
