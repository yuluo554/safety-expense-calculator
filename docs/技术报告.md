# 技术报告：企业安全生产费用提取与使用合规计算工作台

> 版本 0.1.0 · 2026-10-14 · 系列：ai-tool-project-sprint（本地交付形态：Windows 桌面 GUI + CLI 双 exe + 离线 CLI 工具链）
> 本文是面向技术读者的整体说明：架构、关键工程决策、质量门禁与验收证据。逐条 DoD 证据见 [plan/HANDOFF-M1~M5.md](../plan/)。

## 一、问题与定位

企业安全生产费用（财企〔2012〕16号 → 财资〔2022〕136号）的"提取—使用—披露"合规链路有三个反复出错的环节：

1. **按什么标准提**：十二个行业、三类计提机制（按产量/按营业收入超额累退/按工程造价比例）、行业变体（高瓦斯/突出矿井等）与跨年版本切换（2012 版 → 2022 版）；
2. **提多少**：超额累退分段（段区间 `[lower, upper)`、恰好等于分段点归下一段）在手工计算中最易错；
3. **这笔支出算不算合规 / 提够没有**：支出范围四态判定（符合/不符合/未评估/不适用）与使用进度门槛（60%）披露义务。

LLM 聊天给不了**持久规则包**、**逐段可溯的计算**与**全量边界枚举**。本工具是计提与专项审计前的口径防线：全部数值来自版本化规则包（源码零政策字面量），每个结果挂条款依据，每个报告带证据指纹。

## 二、架构

```
┌─ 前端（只渲染） ─────────────────────────────────┐
│  cli/（argparse，零第三方）   gui/（PySide6，惰性导入）│
│   stdout 文本 = format_*  ←── 同一实现源 ──→ 显示块  │
├─ 编排层（唯一入口）───────────────────────────────┤
│  engine/pipeline.py：build_case / compute_calc /   │
│  check_ledger_file / compute_progress_for /        │
│  compute_diff / export_report / selfcheck          │
├─ 领域层（零第三方 + Decimal）─────────────────────┤
│  rules/（加载+status门控） accrual/ tiered/         │
│  spending/ batch/（扫描+对账） ruleset/（diff）     │
├─ 数据（生成器唯一写入者）─────────────────────────┤
│  data/rules（版本化规则包） data/truth（真值库）    │
│  data/samples（演示夹具） data/knowledge（原文底稿）│
└──────────────────────────────────────────────────┘
```

分层不是口号，是**机器可证明的**：

- **GUI 三条 AST 守门**（`tests/test_gui_layering.py`）：不 import 领域层内部模块（唯一入口 `engine.pipeline`）；无算术 `BinOp`（两侧非字符串字面量的 `* / - // % **`）；无政策数值字面量（与引擎侧同一份禁用 token 表）。守门本身可证伪（构造含算术样本必须报错）。
- **CLI/GUI 行为等价**是构造性质：`cli/cmd_*.py` 的 stdout 与 `gui/render.py` 的显示块**直接复用** `pipeline.format_calc/check/progress/diff` 这一组纯函数——对账测试断言三方逐行相等（`tests/test_gui_m5.py`），而不是"都调了同一个函数"的字面声明。
- **输入格式解释唯一实现源**：`build_case`（缺必填字段 → 退出码 2，绝不静默取 0/1）。
- **报告单一渲染源**：Markdown 与 XLSX 消费同一章节结构（`report/sections.py`），XLSX writer 为自写最小 OOXML（零第三方）。

## 三、关键工程决策（节选，全表见 plan/06-决策记录.md）

| 决策 | 结论 | 为什么 |
|---|---|---|
| 核心层零第三方 | 标准库 + Decimal，GUI/打包/台账读入全部惰性导入 | 离线可跑、分发轻；缺 PySide6 → 退出码 3（不崩） |
| 金额全链 Decimal | `ROUND_HALF_UP` 落两位小数 | 费率 0.045 这类值 float 会脏 |
| 规则包版本化 | 「依据文件 × 版本」两套规则包 + manifest 锚定年度 | 双版本对照与"年度 → 规则包"解析是数据问题不是代码问题 |
| status 门控 | `pending` 条目按计算路径分作用域拦截 | "未核对不得进计算路径"是硬约束，不是文档倡议 |
| 基准门槛是数据 | 门槛随 manifest 下发，缺失即退出码 2 | 阈值改动不需要改代码；"没测 ≠ 未达标"（未评估不阻断） |
| 证据指纹 | evidence.json 记录报告 sha256，改一字即检出 | 报告可信度可验证 |
| 时间语义（E21） | 报告默认含真实时间；"逐字节可复现"按 `--fixed-time` 断言 | 不做"号称可复现但实测哈希不同"的假承诺 |
| 本地等价校验 | 本机无远端 → 不写"CI 绿" | CI 已接线（四矩阵），首推后据实补记 |

## 四、质量门禁（全部本机可复现）

1. **冻结产物**：规则包/样本/真值库由三个生成器唯一写入，`--check` 再生成逐字节一致（8+4+130 份）；禁 stdlib random、禁系统时钟、`write_bytes` 防 CRLF 漂移、zip `create_system=0`。
2. **零政策字面量**：`tools/scan_policy_literals.py` 扫 `src/`+`tools/`（token 表片段拼接防自命中），带阳性对照 selftest；85% 阈值等参数一律走数据下发。
3. **脱敏审计**：`tools/dessensitize_audit.py` 三模式 + selftest（合成企业白名单号段、台账一律合成）。
4. **基准三套件**（`safefee bench`，门槛随 manifest）：
   - `tiered_boundary` 216/216（72 个有限边界 × ±0.01 邻域）；
   - `dual_version` 42/42（21 组两版配对）；
   - `synthetic_ledger` 129/129（122 算例 + 7 误报对照）。
5. **可证伪探活**（M4 实测留痕，E23）：每套件注入一次缺陷在数据目录副本上实跑 `bench`，全部实测变红（退出码 1）——"探活只是写了没跑过"是本系列明令禁止的反模式。
6. **测试**：202 项 py3.8 + py3.12 双绿（含 M5 新增 16 项：三方对账 4、复现 4、界面冒烟 8）。

## 五、桌面交付（M5）

- **双 exe**（PyInstaller 6.22 onedir，`py -3.12` 通道）：`safefee.exe`（控制台）+ `safefee-gui.exe`（窗口态）。spec 入仓（`tools/safefee_cli.spec` / `tools/safefee_gui.spec`）。
- **随包数据白名单**：`rules` / `truth` / `samples` 三目录进 `_internal/data/`——核对底稿（`knowledge/raw`）不进发行包；数据目录定位冻结分支（`data_paths.find_data_dir`）按 `_MEIPASS` → `exe目录/_internal/data` → `exe目录/data` 优先级命中。
- **构建后断言 + 中立目录验收**（`tools/verify_frozen.py`）：清空 `SAFEFEE_DATA_DIR`、以 exe 目录为 CWD——selfcheck（数据目录定位在发行包内）、bench 三套件达标、calc/check/progress/diff 全链、calc --out 与 diff --out 三件产物、GUI 包结构（PySide6 内嵌 + 数据白名单）。
- **演示素材可复现**（E21 口径）：`calc --out --fixed-time` 同输入两次导出，MD/XLSX/evidence sha256 一致（测试锁定）；差异对照报告默认即字节冻结。

### GUI 界面

四页签：**计提计算**（档案表单 → 计提结果 + 报告导出）、**支出核查**（档案 + 台账 CSV → 四态逐笔）、**使用进度**（应计提/实际使用 → 门槛与披露义务）、**版本对照**（两年度 → 差异清单 + 对照报告导出）。全部动作走 `engine.pipeline` 公开函数；结果显示块与 CLI stdout 同一实现源（§二）。

## 六、已知边界与显式 pending

- 安全生产法 2014/2021 修正日期、GB 12268 现行版本号：官方渠道（flk.npc.gov.cn / npc.gov.cn / mem.gov.cn）基准日实测不可直连，`clauses.json` 显式登记 `status=pending, value=null`——**不阻断计算路径**（未核对不得进计算路径的门控反过来保证了这点）。
- 2012 版使用进度门槛：办法无对应比例条款，进度判定显式"不适用"。
- 支出核查是**关键词命中型四态判定**（命中允许条目=符合、命中红线=不符合、其余=未评估），不是自由文本语义理解；"风险提示 ≠ 判定"是伦理边界，报告免责声明固定输出。
- 台账一律合成（虚构企业名 + 测试号段），全本地零上传。
